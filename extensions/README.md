# Extensions

Each feature (calendar, lists, Quick add, the board, records, …) is one package here. See
[docs/architecture.md](../docs/architecture.md) §4–7 for the contract and the reasons behind the
boundaries, and [AGENTS.md](../AGENTS.md) for the checklist.

```
extensions/<id>/
├── package.json        # exports "./contract", "./server", "./web", "./api"; the manifest in "famos"
├── openapi.json        # generated by `pnpm gen`
└── src/
    ├── contract/       # Zod schemas, route + action + event types — importable by any extension
    ├── server/         # actions, routes, jobs, migrations, queries — loaded by the server at start
    ├── web/            # Svelte pages, widgets, draft presenters — built into the package, loaded by the browser
    │   └── api.gen.d.ts  # the extension's route types ("./api"), generated by `pnpm gen`
    └── messages/       # en.json and one catalog per bundled language
```

Rules (enforced by `.dependency-cruiser.cjs`): import only `@famos/sdk`, `@famos/ui`, `@famos/time`,
`@famos/i18n` and other extensions' `./contract`; `./web` may also import `@famos/api-client` and the
`./api` types of an extension it depends on. No foreign keys into other extensions' tables; talk to
other extensions through actions, events and typed IDs. The server and the web app import no
extension: they load the packages they find.
